## Confirmed journeys and effects

1. Launch from an explicitly chosen OS working directory; Browse may inspect that root and descendants only, with launching account permissions. No browser-granted server OS permission and no arbitrary escape. Directory contents are real: existing files are visible; new folders, text files, notebooks and project artifacts exist there. Permission failures remain failures. Existing private notebook/project data remain untouched until the user explicitly chooses verified **Move into workspace**. Do not point the current private flat NotebookStore at a public directory or rename legacy files on startup.
2. `/` is a VS Code–style welcome page in Europa's current theme, with Start actions, global recent notebooks and Browse directly below. It is neither a generic metrics dashboard nor a forced editor/runtime launch. Browse is Jupyter-style: choose a plain folder → contents; choose a recognized project folder or project descriptor → project welcome. Project welcome shows project-scoped recent notebooks, Browse files, Back to Europa Home at top-left of *content*. Project is a real directory with a validated Europa descriptor and only files/subfolders inside it as members. No external references or arbitrary host traversal.
3. A `.ipynb` opens the existing Phase 3G editor; text files `.txt`, `.py`, `.md` and other supported UTF-8 text open a simple separate editor with revision/externally-modified conflict protection. Opening `.py` does not execute it. Temporary drafts and uncertain operations remain recoverable; Save is an explicit guarded commit. A browser download/export or upload is *not* in scope.
4. Europa wordmark returns Home via shared guard. File menu ends with **Close Notebook** (no Return Home or duplicate Close); close returns to verified project welcome or Home, retaining kernels and drafts on cancellation. Back/Forward, refresh, deep links, missing entries and parent lookup under latency must recover honestly. Explicit move into/out of a project updates both real location and authoritative association, without deleting documents. Filesystem and SQLite are not transactionally atomic: moves must be idempotently recoverable, not claimed atomic.
5. H2: notebook-scoped Kernel Start explicitly provisions/connects without cell execution; Stop and Restart warn about loss of Python variables and observe accepted/pending/terminal/uncertain outcomes without leaking kernel IDs or bypassing ownership/receipts. Running sessions/status appear on Home. No status lookup provisions a runtime. Preserve idle cleanup and revision guards.
6. Quit and Logout are clearly **disabled Coming later** controls at the top-right of main and project welcome. Functional app shutdown/logout are deferred **beyond 3H**, by latest owner clarification; do not implement browser no-op clickable controls or claim 3H shutdown completion. This supersedes the original H3 shutdown requirement. No Phase 4 agents.

## Planned module seams and source scope

- `api/src/workspace/` (new): root-confined descriptor-relative tree and operations behind a small interface: list, create, read/save text, project descriptor, move. Use opaque IDs or validated path segments, do not pass raw resolved host paths to browser; make external edits and permission changes visible. Validate symlinks/hardlinks, nonregular/binary/oversized files, Unicode names, sibling collisions, parent cycles, and root escape. Never broaden backend process permissions. Path-based notebook identity/revision/receipt continuity needs an explicit mapping/reconciliation seam before enabling notebook moves.
- `api/src/notebooks/store.py`, `api/src/application/store.py`, `api/src/main.py` and narrow routers: retain private flat legacy data; add versioned migration and registered physical locations if necessary; keep membership/recents semantics consistent with containment and preserve v0–v4 data. Test startup/restart and incomplete moves. Read `docs/notebook-persistence.md`, `docs/conversational-notebooks.md`, `docs/runtime-lifecycle.md`, `docs/runtime-recovery.md` before these edits.
- `web/src/Navigation.tsx`, new welcome/browse/text-editor views, `web/src/Pages.tsx`, `web/src/main.tsx`, matching CSS: one guarded navigation path; no duplicate confirmations or editor rewrite. Responsive desktop/390px captures from disposable fixtures. No private owner data in screenshots or Git.

## Reviewable checkpoints (serial)

- **H1-A:** Read-only launch-root Browse and root security tests, with existing-file visibility and project descriptor validation; no implicit migration. Failing permission/symlink cases remain inaccessible.
- **H1-B:** Real create/move and revision-safe text editing, project welcome and global welcome; preserve legacy notebooks. Do not pretend a file lives on disk before that write is durable. A project folder is not simply an old SQLite project with a changed label.
- **H1-C:** Real `.ipynb` creation/open/recovery inside root, explicit verified legacy move, physical moves and membership reconciliation, safe editor close, screenshots and full frozen-candidate regression. Stop for owner H1 review. Old Phase 3G 409 and readiness failures require actual diagnosis, not timeout or safety-guard suppression.
- **H2:** Notebook-scoped read-only status, running sessions and verified Start/Stop/Restart. Build/run the affected Python/frontend/Chrome regression and ownership tests. H3 application termination is intentionally removed by the owner; final documentation states this limit.

**Acceptance:** primary browser journey on real disposable root; no root escape, data loss, duplicate recent visits or implicit runtime provisioning; project/file location and kernel semantics agree with UI; source and final artifacts frozen before full suite; screenshots visually inspected; full required regressions pass or milestone remains incomplete. Required browser failures or infrastructure skips are explicitly recorded. Never commit the completed milestone or claim full 3H while they remain.
